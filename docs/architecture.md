## 业务边界

M1 维护个人预约与签到违约；M2 维护整教室申请和审批；M3 维护维修工单；D 提供身份、主数据、通知和审计。D 子域归属待定。

优先保持一个仓库。后端服务进程数量、数据库 schema 边界及调用拓扑尚未确定。最终至少一条跨模块链路必须真实通过网络公开接口运行，应在第二周前落实拓扑，不能到期末才改造。

## 接口待约定

- 用户身份、角色、院系与数据权限如何传递及验证。
- 教室/座位标识、时间格式、时区及区间边界。
- 占用或下架来源、业务 ID、有效期、幂等键与撤销语义。
- 错误格式、超时、重试和失败补偿。
- 接口变更的兼容与评审方式。

资源是否可预约需要综合仍有效的限制判断，不使用一个不带来源的布尔字段包办所有状态。

## 第一条工程链路

前端页面 → 后端教室查询接口 → 数据库真实数据。验收后扩展为登录 → 搜索 → 预约 → 查询记录。

本方案没有决定审批冲突或维修取消预约策略，这些属于 requirements.md 中的待定业务规则。
