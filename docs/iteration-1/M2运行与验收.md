# M2 首次迭代：兼容当前 main 的接入说明

本次基于 main `0a5dba2` 接入 M2，遵守 [数据库统一契约](../database-contract.md)、[公共层接入指南](../public-layer-integration.md) 和首次迭代 M2 表设计。关联任务 #10，原首次迭代范围已由 M2 负责人确认；完整需求中的多级审批等仍需后续实施。

## 功能与接口

- 有效 TEACHER 身份且具有 USER 角色可以创建整室申请。客户端不能指定其他申请人。
- 本人分页列表、详情与操作轨迹；ROOM_ADMIN 可查看全部测试申请和仅本人申请。
- 管理员单级通过或驳回，禁止自审，驳回意见必填。
- 本人只能撤销 PENDING 申请，重复撤销幂等。
- 批准时重新检查容量、当前申请人资格、院系、启停、未来同日整点、开放时间和公共日期窗口。
- 冲突返回 409，整个事务回滚，申请保持 PENDING。管理员可明确驳回。
- 待审不占用资源。已通过且使用时间已结束时，status 保持 APPROVED，display_status 为 ENDED。

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/v1/m2/applications` | 首次创建 201；相同键/内容重试 200；不同内容 409 |
| GET | `/api/v1/m2/applications` | page、page_size（1–100）、status、mine |
| GET | `/api/v1/m2/applications/{id}` | 本人或 ROOM_ADMIN 可读，附 events |
| POST | `/api/v1/m2/applications/{id}/review` | passed 为布尔值，comment 最多 500 字，驳回必填 |
| POST | `/api/v1/m2/applications/{id}/cancel` | 本人待审撤销，重复撤销返回原结果 |

创建字段：room_id、title（1–100字）、purpose（1–4000字）、participant_count（正整数且不超过容量）、start_at、end_at（含时区）、request_key（UUID）。ID 输出为字符串，数据库 DATETIME(3) 存 UTC，页面明确使用北京时间。

相同申请人/request_key 必须对应相同归一化内容，不能换教室或时段。前端相同表单重试保留请求键。重复审批相同决定保留首次审批人、时间、意见和日志，相反决定返回 409。

## 与 M3、D 的兼容边界

M2 仅维护 m2_applications。资源写入只调用 D 的 lock_room、occupy_room 等公开服务，日志通过 record_operation/list_operations。先锁教室，再锁申请；HTTP Db 统一提交/回滚，M2 不自行 commit 或开启新事务。

- M3 开始维修会阻止 M2 新批准。
- M3 提交完工、验收驳回期间仍保持维修限制。
- M3 验收通过只释放该维修来源，不释放既有 M2 占用。
- M2 不修改 M3 的工单、评价、升级、超时任务、通知或页面。
- D 的认证、资源、通知、主数据模型及服务和 0001–0003 迁移保持 main 原样。
- 本轮不发布 M2 站内通知，不改变 D 通知格式或通知中心的 M3 跳转白名单。
- 现有前端导航、会话失效处理、M3 工单路由和通知中心均保留；M2 表单样式限定在自己的页面内。

共享文件只做以下接入调整：

## 迁移与运行

新增迁移 `0004_m2_applications`，唯一父版本是 `0003_m3_extensions`。它只创建 M2 表和该表的约束/索引，不修改已合并的公共表或 M3 表。

已有 main 数据库先检查 Alembic 版本，按 README 安装依赖并配置本地 .env 后运行：

```bash
cd backend
.venv/bin/python -m alembic current
.venv/bin/python -m alembic upgrade head
.venv/bin/python -m scripts.seed
.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

在 frontend 执行 npm ci、npm run dev。后端端口不同可在 frontend/.env.local 中设置 VITE_API_PROXY_TARGET，使用 main 已有的代理配置，无需改共享代码。

页面入口 `/m2/applications`。使用现有种子账号 teacher 提交、room_admin 审批；密码来自 SEED_USER_PASSWORD。演示教室容量为 3，人数需在 1–3 之间。公共资源页可验证对应时段全部座位为整室占用。

**旧试验库提示：** 若数据库仍记录此前 M2 实验版本 `c229e10bbc03`，不能把它当成当前 main 的 `0003_m3_extensions` 直接升级，不能手改 alembic_version 或删表冒充迁移。本次使用独立数据库验证当前 main 的空库重放和 0003 → 0004 升级；旧试验数据转换需另行制定迁移方案，原本地数据保留。

回退到 `0003_m3_extensions` 会删除 M2 表和其中数据，M3/D 表保持不变。有业务数据时先备份并协调已批准 M2 来源，不能留下失去申请单的有效占用。本次仅在专用测试库验证回退，不在业务库执行回退。

## 验证方法

MySQL 测试必须显式使用可清空且以 _test 结尾的独立数据库。示例：

```bash
cd backend
# 在环境中配置专用 TEST_DATABASE_URL，不得使用业务库
.venv/bin/python -m ruff check app scripts tests alembic
.venv/bin/python -m pytest --require-mysql -q
cd ../frontend
npm run build
```

M2 测试覆盖权限、时间和容量、院系限制、幂等、分页与详情授权、审批重校验、M1/M2/M3 来源冲突、故障回滚和真实并发。

新增 test_m2_compatibility.py 通过 M3/D 的应用 HTTP 路由验证（TestClient 同进程执行，不是跨进程网络集成）：报修、派单、维修、完工、驳回返修、验收完成、评价和通知继续工作；维修限制能阻止 M2；释放维修不误释放 M2；M2 迁移升级/回退逐行保留已有全部 D/M3 数据。
