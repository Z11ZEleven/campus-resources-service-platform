# M2 首次迭代：运行与验收

本次实现对应 [M2 首次迭代表设计](第一次功能迭代-M2教室审批表设计.md) 和 [公共层接入指南](../public-layer-integration.md)，关联任务 #10。范围已由本次开发请求者选择；不表示全组已评审通过完整需求。

## 实现范围

- 有效 TEACHER 身份且具有 USER 角色的用户提交整教室申请。
- 本人分页列表、详情与操作轨迹；ROOM_ADMIN 可查询全部测试教室申请，支持仅本人和状态过滤。
- 管理员单级通过/驳回；禁止自审，驳回意见必填。
- 本人撤销 PENDING 申请；重复撤销幂等。APPROVED、REJECTED 不允许撤销。
- 批准通过公共 `occupy_room` 创建 M2 整室来源；资源冲突返回 409，申请保持 PENDING。
- 前端入口 `/m2/applications`，复用登录、公共布局、Axios 和资源查询。

## 与完整需求的差异

| 规则 | 本轮口径 | 后续范围 |
|---|---|---|
| 申请资格 | TEACHER + USER | 学生/工作人员申请资格 |
| 审批 | ROOM_ADMIN 单级、全体测试教室、禁止自审 | 院系/校级一级与教室二级、细粒度数据范围 |
| 时间 | 北京时间、未来整点、同日、教室开放时段内；复用 D 预约窗口，默认今天起 7 天 | 提前两个自然日及独立 M2 时间策略 |
| 时长 | 不套用 M1 的 4 小时上限 | 完整需求的 1–4 小时规则另行协调 |
| 教室 | 复用现有有效且院系允许的教室 | 仅整室预约模式及归属字段 |
| 冲突 | 返回 409 并保持 PENDING，由管理员决定是否驳回 | 自动驳回冲突申请 |
| 集成 | 同进程公共服务、同一个数据库事务 | 真实网络接口及失败恢复 |
| 自动任务 | 无 | 多级审批超时、提醒与通知 |

以上差异由首次迭代边界决定，没有修改 D 的公共角色、资源规则或数据表。真实网络跨模块调用仍未完成。

## 启动

先按仓库说明启动 MySQL，并准备 `.env`、Python 依赖和前端依赖。

```bash
cd backend
.venv/bin/python -m alembic upgrade head
.venv/bin/python -m scripts.seed
.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

另一个终端在 `frontend` 运行 `npm run dev`。进入 `/m2/applications`。

账号与密码沿用现有种子：`teacher` 提交，`room_admin` 审批，`student` 查看公共座位状态。密码读取本地 `SEED_USER_PASSWORD`，不在仓库写入密码。种子教室容量为 3，演示申请人数应为 1–3。

## HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/m2/applications` | 首次创建 201；相同键与内容重试 200；不同内容 409 |
| GET | `/api/v1/m2/applications` | `page`、`page_size`（1–100）、`status`、`mine` |
| GET | `/api/v1/m2/applications/{id}` | 本人或 ROOM_ADMIN 可读；附 `events` 操作记录 |
| POST | `/api/v1/m2/applications/{id}/review` | `passed` 布尔值、`comment` 最多 500 字；驳回必填 |
| POST | `/api/v1/m2/applications/{id}/cancel` | 本人撤销待审；已撤销重试返回原单 |

创建字段：`room_id`、`title`（1–100 字）、`purpose`（1–4000 字）、`participant_count`（正整数且不超过容量）、`start_at`、`end_at`（带时区）、`request_key`（UUID）。申请人来自登录身份；额外字段如 `applicant_id` 被拒绝。ID 输出为字符串，时间输出为 UTC Z，页面明确按北京时间输入/展示。

同申请人相同 `request_key` 必须对应完全相同的归一化内容；相同键不能换教室或时段。前端在相同表单内容失败后重试时保留该键。审批重复同一决定返回已有结果，保留首位审批人、时间、意见和日志；相反决定返回 409。

已批准且结束时间已过时，`status` 仍为 APPROVED，`display_status` 为 ENDED。列表的 APPROVED 过滤包含已结束申请。

## 事务与迁移

- 新增迁移 `c229e10bbc03`，依赖 `0001_public_layer`，仅增加 `m2_applications`。
- HTTP `Db` 负责提交/回滚。M2 服务只 flush，不创建嵌套事务或独立 Session。
- 创建先锁教室，再查申请人请求键；修改先读取不可变教室 ID，再锁教室、锁申请并复查状态。
- 审批会重新检查申请人资格、当前教室容量、院系、启停、未来时间、开放时段和真实来源冲突。
- 待审不写资源来源。通过后的来源、公共审计、申请状态、房间版本在同一事务提交。
- 追加 `CREATE_APPLICATION`、`REVIEW_APPLICATION`、`CANCEL_APPLICATION` 日志，复用 D 的资源获得日志。
- 公共接入文件变更仅限后端路由注册、模型元数据注册和前端导航/路由；公共层规则与原迁移不变。

回退会删除 M2 申请表和其中数据；有数据时先备份并由负责人确认。不能仅删除 M2 表而保留已批准的资源来源后继续运行旧版本，否则会留下失去业务单的占用。本次只在独立测试库验证迁移往返；业务库不执行回退。

## 验证方法

仅对显式配置、可清空且以 `_test` 结尾的数据库运行集成测试：

```bash
cd backend
# 在环境中设置 TEST_DATABASE_URL=mysql+pymysql://测试账号:密码@127.0.0.1:3306/campus_resources_m2_test
.venv/bin/python -m ruff check app scripts tests alembic
.venv/bin/python -m pytest --require-mysql -q
cd ../frontend
npm run build
```

`tests/test_m2.py` 覆盖权限、字段/时间/容量、部门限制、幂等、分页与详情授权、审批重校验、M1/M2/M3 冲突、相邻时段、资源展示、故障回滚、数据库约束、迁移往返，以及真实并发创建、批准与撤销。

关键并发测试 `test_cancel_waits_for_room_lock`：临时去掉 M2 修改路径的房间锁时应失败，恢复后应通过。故障验证只在独立测试库中进行，不把跳过数据库测试视为通过。

浏览器验收：教师新建明日的申请 → 退出并以 `room_admin` 登录 → 查看用途与时段 → 通过 → 公共资源页选择同一教室/日期，确认对应小时的全部座位为“整室占用”。另外验证驳回和待审撤销。

## 已知限制

本轮没有多级审批、超时撤销、通知、已批准撤销/改期、独立 M2 教室开放模式、动态数据范围和网络集成。教室下拉沿用公共示例的前 100 间限制；申请列表自身有分页。前端 Token 放内存，刷新需要重新登录。以上不代表完整课程需求已完成，人工验收与合并由团队负责。
