# 第一次功能迭代：M1 座位预约表设计

> **版本：第一次功能迭代（Iteration 1）**  
> 日期：2026-10-21。数据库统一为 **MySQL 8.4 + InnoDB + utf8mb4**。  
> 本文件是待团队确认的最小实现设计，不是最终需求完成声明；仅提供设计，不执行建表。

## 1. 本轮目标

登录 → 搜索教室/座位 → 选择整点时段 → 提交预约 → 查看我的预约 → 开始前取消。

| 本轮实现 | 后续必须补齐 |
|---|---|
| 预约、取消、历史列表、院系和开放时间检查 | 动态签到编码、签到与未签到处理 |
| 插座筛选、最长 4 小时、并发冲突校验 | 开始前 15 分钟/开始后 10 分钟提醒、15 分钟违约取消 |
| 读取 M2/M3 资源限制 | 违约记录、历史一键复用、运营统计和完整配置 |

本模块只建 **1 张业务主表**，公共用户、座位、来源和操作记录全部复用 D。

## 2. 字段设计

### `m1_reservations`：座位预约单

| 字段 | MySQL 类型 | 可空 | 说明／约束 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | 否 | 自增主键 |
| `created_at` | DATETIME(3) | 否 | 创建时间，UTC |
| `user_id` | BIGINT UNSIGNED | 否 | FK → d_users.id，从登录身份获取 |
| `room_id` | BIGINT UNSIGNED | 否 | FK → d_rooms.id |
| `seat_id` | BIGINT UNSIGNED | 否 | FK → d_seats.id，必须属于 room_id |
| `start_at` | DATETIME(3) | 否 | 预约开始，UTC |
| `end_at` | DATETIME(3) | 否 | 预约结束，UTC |
| `status` | VARCHAR(16) | 否 | RESERVED / CANCELLED |
| `cancelled_at` | DATETIME(3) | 是 | 取消时间 |
| `cancel_reason` | VARCHAR(255) | 是 | 取消原因 |
| `request_key` | CHAR(36) | 否 | 客户端本次创建请求的 UUID；重试复用 |
| `updated_at` | DATETIME(3) | 否 | 更新时间，UTC |

- UNIQUE(user_id, request_key)；同键同内容返回原结果，同键不同内容返回 409。
- 索引 (user_id, created_at)、(room_id, start_at)。
- 仅 RESERVED 生成 ACTIVE 的 M1 资源来源。开始前允许本人取消，状态、来源、日志一起更新。
- 已过 end_at 的 RESERVED 在响应中计算 display_status = ENDED，不依赖后台任务改主状态；不再占用未来时段。
- 第一轮不存 user_identity_id：由 UNIQUE(user_id) 的公共身份取得院系；后续多身份再加身份快照关联。

## 3. 公共依赖

| 表 | 用途 |
|---|---|
| d_users、d_user_identities | 有效用户、学生身份、院系资格 |
| d_rooms、d_seats | 开放时间、启停、插座与座位归属 |
| d_resource_blocks | 以 source_module = M1、source_id = 预约 ID 记录占用 |
| d_seat_status_summary | 搜索展示；提交时仍查来源 |
| d_operation_logs | 创建、取消记录 |

## 4. 业务校验

- 预约人来自登录态，第一轮 STUDENT 身份且具有 USER 角色可以预约。
- 起止均为北京时间整点，同一天，时长为 1～4 小时；最大值和可预约窗口从公共配置类读取。
- 只能预约未来时间，且在允许日期窗口内、教室开放时段内。
- 教室/座位启用；院系教室匹配用户身份中的 department_code。
- 按 D 约定先锁房间并检查来源冲突；禁止仅查汇总。
- 首轮不实现跨教室“同用户同时段最多一个预约”限制；该规则待组内确认，后续若加入需增加用户级并发控制，不能声称已有房间锁覆盖此规则。

## 5. 接口与页面

| 方法 | 路径 | 权限/行为 |
|---|---|---|
| POST | /api/v1/m1/reservations | 创建预约，201；幂等重试返回原记录 |
| GET | /api/v1/m1/reservations | 仅本人列表，支持状态过滤 |
| GET | /api/v1/m1/reservations/{id} | 仅本人详情 |
| POST | /api/v1/m1/reservations/{id}/cancel | 本人、开始前；重复取消返回当前结果 |

前端：座位搜索页（调用公共资源接口）、我的预约页；创建/取消用弹窗。

## 6. 创建与取消事务

创建：开启事务 → 锁房间 → 校验身份和时段 → 复查幂等键及来源 → 写预约 → 写 M1 来源 → 写日志 → 增加 resource_version → 提交。

取消：按不可变 room_id 锁房间 → 锁定并复查预约 → 更新 CANCELLED → 仅释放该 M1 来源 → 写日志及版本 → 提交。

日期窗口按北京时间计算；数据库以 UTC 保存。固定区间按 [start_at, end_at) 比较，10:00 结束不阻塞 10:00 开始的新预约。

## 7. 验收

- 合法预约成功，刷新后可查；取消后可再次预约该时段。
- 同座位重叠预约被拒绝；并发请求最多一个成功。
- 同室不同座位不被错误冲突拦截。
- M2/M3 限制生效后不能创建新的冲突预约。
- 越权查看、取消他人预约及无效院系预约被拒绝。
- 尚未签到、提醒、违约，不在汇报中宣称完整 M1 已完成。
