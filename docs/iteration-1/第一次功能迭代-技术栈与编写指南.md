# 第一次功能迭代：技术栈与统一编写指南

> **版本：第一次功能迭代（Iteration 1）**  
> 日期：2026-10-21。数据库固定为 **MySQL**，不再使用上一稿中的其他数据库类型、schema 和排斥约束设计。  
> 本文件指导后续编写；本次只创建文档，没有搭建应用、执行迁移或配置流水线。

## 1. 本轮总体安排

**一个仓库、一个 Vue 工程、一个 FastAPI 进程、一个 MySQL 数据库。**

| 模块 | 本轮业务表 | 最小功能 |
|---|---|---|
| D | 8 张公共表 | 登录、固定角色、用户身份、教室座位、统一来源、小时汇总、最小操作记录 |
| M1 | m1_reservations | 搜索、预约、查看、开始前取消 |
| M2 | m2_applications | 提交、单级审批、待审撤销、整室占用 |
| M3 | m3_work_orders | 上报、派单、维修、完工、验收、维修限制 |
| 合计 | **11 张表** | 跑通基本业务及同进程状态联动 |

本轮不引入 Redis、消息队列、Celery、微服务网关和分布式事务。三个模块通过 D 的公共资源 service 集成，但保留公开服务边界。课程最终要求的真实跨模块网络调用留作后续明确任务，本轮同进程调用不能冒充最终网络集成。

## 2. 统一技术栈

| 层次 | 选型 | 编写要求 |
|---|---|---|
| Python | 3.12 系列 | 全组和 CI 使用相同小版本 |
| 后端框架 | FastAPI | APIRouter 分模块；Pydantic 请求/响应模型 |
| HTTP 服务 | Uvicorn | 本地 --reload；部署不使用开发热重载 |
| ORM | SQLAlchemy 2.0 系列 | 本轮同步 Session，普通 def 路由，避免混用同步 DB 与异步协程 |
| MySQL 驱动 | PyMySQL，启用 rsa 依赖 | 连接串 mysql+pymysql，兼容认证所需依赖 |
| 数据库 | **MySQL 8.4 系列** | InnoDB、utf8mb4、严格模式；所有环境一致 |
| 迁移 | Alembic | 一套迁移目录，全组协调版本 |
| 配置 | pydantic-settings + .env | .env 不入库；只提交占位 .env.example |
| 登录 | PyJWT + pwdlib[argon2] | Bearer Token；密码哈希，不手写签名或哈希 |
| 前端 | Vue 3 + TypeScript + Vite | 一个工程，按模块拆页面 |
| Node.js | 22 系列，至少 22.12 | 初始化时确认工具要求，全组锁定同一版本 |
| 组件与路由 | Element Plus + Vue Router | 共用布局、登录和菜单 |
| 前端状态 | Pinia | 保存当前用户和本次登录状态 |
| HTTP 客户端 | Axios | 一个请求实例，统一 Token 与错误处理 |
| 后端测试 | pytest + httpx | 测真实权限和业务；数据库测试使用 MySQL |
| 格式检查 | Ruff；前端 ESLint | 提交前执行 |
| 本地依赖 | Docker Compose 启动 MySQL | 初期前后端直接本机运行即可 |
| CI | GitHub Actions | 实际后端测试、前端类型检查与构建；后续接测试部署 |

具体依赖补丁版本由工程初始化者安装、验证后锁定，其他成员按锁文件安装，不各自升级。

## 4. 数据库约定

| 项目 | 统一方式 |
|---|---|
| 数据库名 | campus_resources |
| 表名 | d_users、m1_reservations 等前缀；MySQL 的 schema 是数据库同义概念，本轮不按模块另建数据库 |
| 引擎和字符集 | InnoDB、utf8mb4；数据库与表统一排序规则 |
| ID | BIGINT UNSIGNED 自增；外键类型一致；JSON 响应中 ID 统一为字符串 |
| 时间 | DATETIME(3) 存 UTC；DATETIME 不自动携带时区，转换由应用负责 |
| 数据库连接时区 | +00:00 |
| 开放时段 | rooms.open_time、close_time 使用北京时间 TIME，比较前将请求转换到业务时区 |
| 时间区间 | [start_at, end_at)，相邻时段允许 |
| 状态 | VARCHAR + Python 枚举；首轮不使用数据库 ENUM |
| 隔离级别 | 本轮统一 READ COMMITTED，并使用房间行锁协调资源变更 |
| 迁移 | Alembic 唯一版本链，不手工建表、不用 create_all 代替版本迁移 |
| 删除 | 本轮无物理删除用户、教室、座位和业务单的功能 |
| 索引 | 唯一键与模块文档列出的基础查询索引 |
| 初始化 | 幂等种子脚本，虚构账号与资源；开发密码从初始化环境读取 |
| 配置表 | 本轮不建，统一配置类提供可预约窗口等参数 |

建议连接示例：

```text
mysql+pymysql://campus_app:CHANGE_ME@127.0.0.1:3306/campus_resources?charset=utf8mb4
```

由 SQLAlchemy URL.create 构建连接配置，避免密码中含特殊字符时直接拼接 URL。实际凭据不写进代码或提交记录。

### 时间输入输出

- 输入示例：2026-10-22T09:00:00+08:00。
- 后端转换为 UTC，再写入 DATETIME(3)。
- 读取后明确附加 UTC 语义，输出含 Z 或 +00:00 的 ISO 时间。
- 前端使用 Asia/Shanghai 格式化，不依赖浏览器所在地时区。
- 禁止把无时区日期字符串按各自电脑本地时区随意解释。

## 5. 权限和本轮业务规则

| 身份/角色 | 本轮能力 |
|---|---|
| USER + STUDENT 身份 | M1 预约；M3 上报；查看本人记录 |
| USER + TEACHER 身份 | M2 申请；M3 上报；查看本人记录 |
| USER + STAFF 身份 | M3 上报；查看本人记录 |
| ROOM_ADMIN | M2 审批全部测试教室的申请，不审批本人申请 |
| PROPERTY_ADMIN | M3 派单、验收全部测试教室，不验收自己维修的工单 |
| REPAIRER | 查询并处理分配给自己的工单 |
| SYS_ADMIN | 本轮仅显式配置的公共管理能力；如需业务能力则另授对应角色 |

固定权限映射由 auth 负责人统一编写。角色取自 d_user_roles；身份取自 d_user_identities；所有操作先检查用户、身份是否有效。前端菜单不代替后端鉴权。

登录：

- POST /api/v1/auth/login，JSON 输入 username、password。
- 响应 access_token、token_type=bearer；使用 HTTPBearer 接入接口鉴权。
- Token 含字符串 sub、exp 等必要声明，服务端固定算法、校验签名和期限。
- JWT_SIGNING_KEY 由运行环境提供；本轮访问令牌建议 60 分钟，不做刷新令牌。
- 每次请求重新检查有效用户与角色。客户端退出清除本地状态；既有 Token 到期前仍有效，用户禁用后请求立即被拒绝。
- 前端 Token 首轮放 Pinia 内存，刷新后重新登录，避免同时开发持久会话机制。

## 6. 统一资源事务：必须照同一规则写

### 6.1 调用边界

业务 service 开启唯一事务，D 的资源/日志函数接收同一个 Session，只 flush、不自行 commit。三个模块仍只通过公共函数操作 D 的资源表，不跨模块修改其他业务单。

### 6.2 统一步骤

1. 根据不可变 room_id，按主键 SELECT d_rooms ... FOR UPDATE。
2. 再锁定并复查本业务单；新建请求则在锁后复查幂等键。
3. 检查最新身份、资源启停、开放时间和真实 d_resource_blocks。
4. 写业务状态、来源、操作记录；影响可用性时递增房间 resource_version。
5. 全部成功后提交；任何失败整体回滚。

所有路径顺序一致：房间 → 业务单 → 来源/日志。禁止某接口先锁业务单、另一接口先锁房间。事务中不执行邮件或外部 HTTP 调用。

### 6.3 时间冲突

对本轮 M1/M2 的有限申请区间，相交条件：

```text
existing.start_at < requested.end_at
AND (existing.end_at IS NULL OR existing.end_at > requested.start_at)
AND existing.status = ACTIVE
```

| 操作 | 检查/写入 |
|---|---|
| M1 新预约 | 查同座位 M1，以及同室 M2/M3；写座位级 M1 来源 |
| M2 批准 | 查同室所有重叠 M1/M2/M3；无冲突才写整室 M2 来源 |
| M3 开始 | 可与已有占用并存，写整室 M3 来源，阻止后续新预约 |
| 任一释放 | 只释放 (source_module, source_id)，保留其他来源 |
| 查询汇总 | 版本过期时持房间锁按需重算；预约最终仍查真实来源 |

MySQL 不使用原方案的时间范围排斥约束；普通唯一索引不能证明两个时段不相交。房间行锁是本轮统一并发控制的关键。

本轮不自动取消维修前已存在的预约；只阻止新预约/新批准。需要人员撤离、安全封闭等真实场景时必须另行补充处理规则，不能宣称已经覆盖。

## 7. 接口、错误和前端统一

| 类别 | 前缀/规则 |
|---|---|
| 登录 | /api/v1/auth |
| 公共资源 | /api/v1/resources |
| M1 | /api/v1/m1 |
| M2 | /api/v1/m2 |
| M3 | /api/v1/m3 |
| 公共资源列表 | GET /rooms、/rooms/{id}/seats |
| 小时可用性 | GET /rooms/{id}/availability?date=YYYY-MM-DD |
| 分页 | page 从 1 开始，page_size 默认 20、最大 100 |
| 列表响应 | items、total、page、page_size |
| 详情 | 直接返回响应模型，字段白名单，不输出密码哈希 |
| 错误 | 统一 HTTPException.detail，含 code、message；Pydantic 422 校验格式保留标准形式 |
| HTTP | 401 未登录；403 无操作权限；404 不存在/不可见；409 状态或资源冲突；422 参数不合法 |
| 创建 | request_key 同次请求重试复用，按创建人组合唯一；不能每次重试都生成新键 |

新建普通业务返回 201；同键重试可返回 200 原对象。对相同键但不同业务参数返回 409。

前端共用 request.ts 加 Authorization、统一错误提示；一个登录页和一个导航。Vite 代理 /api 到后端，部署时 Nginx 同域代理，不让每组自行配置跨域例外。

## 8. 本地初始化与运行

以下是后续工程落地后的约定命令；文档本身不包含实现，命令依赖相应文件和脚本完成。

### 后端初始化者

在 backend 目录创建虚拟环境并激活后：

```bash
python -m pip install "fastapi[standard]" "sqlalchemy>=2.0,<2.1" "pymysql[rsa]" alembic pydantic-settings "pwdlib[argon2]" PyJWT pytest httpx ruff
python -m pip freeze > requirements.txt
```

只有工程初始化者生成首个依赖文件，其他人使用：

```bash
python -m pip install -r requirements.txt
alembic upgrade head
python scripts/seed.py
python -m uvicorn app.main:app --reload --port 8000
```

后端健康检查 /health；交互文档 /docs。参数、角色和状态规则仍需真实编写，不能把“能启动”当成业务完成。

### 前端初始化者

从仓库根目录执行 create-vue，项目名选 frontend，启用 TypeScript、Router、Pinia 和 ESLint：

```bash
npm create vue@latest
```

进入 frontend 后安装 Element Plus、Axios，完成运行验证并提交 package.json 和 package-lock.json。其他成员直接：

```bash
npm ci
npm run dev
```

统一提交 .nvmrc 或等效 Node 版本记录。本轮不重复建立多个前端项目。

### 环境示例字段

| 变量 | 示例/含义 |
|---|---|
| MYSQL_HOST | 本机开发 127.0.0.1；容器内使用 Compose 服务名 mysql |
| MYSQL_PORT | 3306 |
| MYSQL_DATABASE | campus_resources |
| MYSQL_USER | campus_app |
| MYSQL_PASSWORD | 占位，真实值仅在 .env/部署配置 |
| JWT_SIGNING_KEY | 独立生成的密钥，不能提交 |
| ACCESS_TOKEN_MINUTES | 60 |
| BOOKING_MAX_HOURS | 4 |
| BOOKING_WINDOW_DAYS | 7；定义为北京时间今天至今天后第 6 天 |
| SEED_USER_PASSWORD | 本地虚构账号初始化密码，不提交真实值 |

不在生产环境自动覆盖已有用户密码。种子按 username、教室 code、室内 seat_no 等自然唯一键幂等插入。

## 10. 开发顺序与验收

| 顺序 | 任务 | 验收 |
|---|---|---|
| 1 | 工程骨架、MySQL、迁移、种子 | 新环境按 README 启动 |
| 2 | 公共登录、身份、教室座位查询 | 四类测试用户可登录，前端显示真实资源 |
| 3 | D 统一资源函数与 M1 | 预约、取消、同座位并发冲突正确 |
| 4 | M2 单级审批 | 通过后阻止个人预约，已有冲突不能通过 |
| 5 | M3 流转 | 开始维修阻止新预约，多工单恢复正确 |
| 6 | 汇总、操作记录、前端整合 | 状态变化可见且可追溯，刷新不丢数据 |
| 7 | CI 与测试部署 | PR 有实际检查，测试环境可重复交付 |

最低检查：

- 后端：python -m pytest、python -m ruff check .。
- 前端：工程初始化时明确脚本，至少类型检查和 npm run build；若没有相应 npm 脚本，先补齐再纳入 CI。
- 数据库：真实 MySQL 验证外键、事务、并发；不能用内存字典或 SQLite 代替并发验证。
- 集成：同座位两请求仅一个成功；不同座位允许；M2/M3 阻塞 M1；两张维修单只关闭一张仍不可用。
- 权限：不可查询、取消或处理无权记录；不能自审或自验收。
- 用一个关键例子故意移除冲突检查，确认测试失败，然后恢复。
