# M2 两级审批实施方案

依据：`docs/m2-requirements.md`、`docs/m2-design.md`。用户本次明确选择完整需求，并允许必要的 D 扩展；不把旧单级首次迭代替代为本次交付，也不把实现提案写成团队已评审结论。

## 功能与边界

1. 学生、教师、工作人员的有效身份均可用本人身份申请；申请只收教室、用途、带时区时段和幂等键，不额外收人数、联系方式或附件。
2. 教室分 SEAT / WHOLE_ROOM，M2 只用 WHOLE_ROOM。提交至少提前两个北京时间自然日、整点、同日、1–4小时、08:00–22:00及教室实际开放时段内。
3. 院系教室由 DEPT_ADMIN 加对应院系范围一级审批；校级教室由 CAMPUS_ADMIN 加对应校级范围一级审批。二级由 ROOM_ADMIN 加具体教室范围审批。禁止自审。
4. 每级在步骤创建后的下一自然日 23:59:59 截止，使用开始先到时以开始为界。本人仅可撤回两类待审状态，终态不可重开。
5. 一级通过不占用。二级同意先持久化 RESOURCE_CONFIRMING 和资源任务，再在数据库事务外通过真实 HTTP 请求 D 独立资源应用。
6. D 按教室锁原子创建 M2 来源并持久化幂等结果。只有确认成功才写 APPROVED；确定冲突写 REJECTED，并自动驳回其他待审重叠申请。技术失败/结果未知保留确认状态并重试。
7. 超时扫描、临期提醒和资源任务持久化、可恢复、幂等。默认临期24小时为可配置实现默认值，待团队评审；不声称已达成团队共识。
8. 超时与资源请求竞态时先自动撤销申请，再持久化取消任务。D 取消命令可以先写取消墓碑，阻止延迟到达的创建；若已占用，只释放该申请来源。网络不通时明确显示资源清理待确认，不假称已经释放。
9. 站内通知复用 D 的真实事务收件箱，不用开发日志冒充通知；业务历史独立保留，系统动作记录系统操作者语义。

## 实现映射

技术无关草案中的 UUID/TIMESTAMPTZ 映射到既有契约的 BIGINT UNSIGNED、JSON字符串ID、DATETIME(3) UTC；不改项目数据库技术栈。

- D：追加教室 booking_mode、campus_code；审批角色与作用域；支持系统审计操作者；追加资源命令结果表与受服务密钥保护的资源 HTTP 应用。D 不读 M2 私有表。
- M2：applications、approval_steps、application_events、resource_jobs；所有业务转换先房间锁后业务锁，并校验状态/version。
- HTTP 编排：普通请求复用 Db；跨网络审批分为明确的本地持久化、网络调用、结果确认阶段，网络阶段不持有数据库事务或房间锁。
- D 应用入口 `app.resource_api:app`，M2/M3 主应用 `app.main:app`。真实网络验证使用独立进程与 TCP，不使用 ASGITransport 冒充。
- M3 业务实现和已有迁移保留；新增迁移接在当前 main 的 `0003_m3_extensions` 后，迁移升级测试保留旧 D/M3 数据。

## 验证与需求追踪

| 需求范围 | 验收 |
|---|---|
| 资格、时间与教室类型 | 三类身份、冒用拒绝、互斥类型、月末年末、整点及1/4小时边界 |
| 两级权限 | 对应角色+范围、自审拒绝、一级不能直接批准、历史可追溯 |
| 撤回与超时 | 两级待审均可撤回、终态不可撤回、自然日截止/使用开始边界、重启补扫 |
| 资源网络 | 真 TCP 成功、冲突、断连、响应丢失、幂等重试、超时取消竞态、来源追溯 |
| 并发与恢复 | 同步骤竞争、审批/撤回/超时竞争、同室重叠最多一份成功、多来源不误释放 |
| 通知与回归 | 审批/临期/终态真实收件箱且不重复；M3/D原有测试、迁移往返、前端构建 |

实现和测试均在功能分支、独立 *_test 数据库中完成。人工验收与合并由团队负责，遇到 Git 冲突由人工处理。
