# M3 报修工单前端接入说明

基础闭环依据第一迭代设计；当前还接入超时升级、一次性评价与站内通知，规则、API 和验证见 [M3 后端](m3-backend.md)与 [M3 扩展说明](m3-extensions.md)。采用 Vue 3、TypeScript、Element Plus，复用公共 Axios、Pinia 登录态和布局。新增公共 D 通知为本次用户确认的本地实现提案，待团队评审。

## 1. 页面与功能

| 页面 | 内容 |
|---|---|
| `/m3/work-orders` | 当前用户可见的工单；筛选、分页、上报、累计升级次数和时限配置；物业管理员手动补扫 |
| `/m3/work-orders/:id` | 故障、进度、处理记录和操作；阶段截止、升级历史及一次性评价 |
| `/notifications` | 本人通知、未读筛选、分页、单条/全部已读和跳转工单 |

桌面显示表格，手机显示工单卡片。时间固定显示北京时间，接口 ID 全程按字符串处理。未登录访问上述地址会先登录，再返回请求页面；刷新浏览器需要重新登录，Token 不持久化到浏览器存储。

| 角色/条件 | 可用操作 |
|---|---|
| USER | 上报可见教室的故障；查看本人上报工单；完成后对自己的工单评价一次 |
| PROPERTY_ADMIN | 查看全部可管理工单；派单；验收通过/驳回；手动补扫超时 |
| 被分配本单的 REPAIRER | 已派单时开始维修；维修中填写完工说明；查看被分配的工单 |
| 多角色 | 取角色权限的并集，但仍受状态、人员归属及禁止自验收约束 |

SYS_ADMIN 无隐式 M3 权限。页面仅提供操作入口，最终权限和数据范围由后端检查；不可访问的详情显示统一的不存在/无权查看提示，不展示工单内容。

## 2. 接口与目录

M3 请求统一经过 `src/api/m3.ts`，路径前缀为 `/api/v1/m3/work-orders`。维修人员选择复用公共 `GET /api/v1/auth/users?role_code=REPAIRER`，教室选择复用公共资源接口，列表页加载全部可见教室选项。详情的教室名称是可选补充查询，名称不可获取时保留教室 ID，不影响已授权工单的展示。其他用户名称若接口未提供则显示用户 ID。

- `frontend/src/views/WorkOrdersView.vue`：工单列表与筛选。
- `frontend/src/views/WorkOrderDetailView.vue`：详情、历史与派单/开工/完工/验收弹窗。
- `frontend/src/components/m3/CreateWorkOrderDialog.vue`：故障上报表单。
- `frontend/src/components/m3/M3ExtensionsPanel.vue`：阶段时限、升级记录、评价提交与未知结果核对。
- `frontend/src/api/notifications.ts`、`frontend/src/stores/notifications.ts`：通知请求、未读数轮询、会话及响应版本隔离。
- `frontend/src/views/NotificationsView.vue`：通知中心与已读操作。
- `frontend/src/utils/m3.ts`：枚举、权限显示、北京时间和历史说明格式化。
- `frontend/src/utils/navigation.ts`：登录后返回本站已知页面及通知工单链接白名单。

## 3. 提交与错误处理

1. 上报时生成 UUID `request_key`。网络或服务器错误导致结果不确定时，锁定本次内容，并保留原 UUID 和完整请求体；用户选择“重试本次上报”时复用它们。关闭再打开弹窗保留本页内草稿；刷新/离开列表会丢失草稿，不提供跨会话持久化。
2. 派单、开工、完工和验收不自动重试 POST。网络或服务器错误时关闭操作弹窗，尝试刷新详情，提示先核对状态与历史，再决定是否重提。
3. 验收弹窗打开时冻结 `expected_completion_round`。收到 409 后关闭弹窗并刷新详情，必须核对新轮次后重新打开确认，不把旧验收意图自动应用到新轮次。
4. 写请求进行时禁止重复提交和关闭弹窗。详情切换、离开页面和快速筛选使用请求取消及顺序检查，旧响应不会覆盖当前工单或筛选结果。
5. 表单检查标题/描述/完工说明长度、必填分类/人员及驳回原因；后端校验错误仍通过统一错误解析显示。
6. 评价 1～5 星、评语至多 500 字；成功显示不可修改结果并刷新完整历史。结果不明先重新获取详情，不自动重发，核对失败时保留输入并要求手动核对。
7. 导航每 30 秒查询未读数；请求不叠加，旧列表不能覆盖较新轮询，登出/切账号取消请求并清空旧数据。通知列表需手动刷新；点击安全工单链接前标为已读。全部已读只处理后端快照中的已送达消息，新消息保持未读。
8. 详情超时标记取最近一次服务器结果，正好截止不超时；自动或人工升级不推进工单状态。扫描网络错误可核对工单后再次补扫，后端阶段去重避免重复升级。

## 4. 本地启动

先按照 `backend/README.md` 与 `docs/m3-backend.md` 配置数据库并升级迁移，启动后端。然后在 `frontend` 目录执行：

```powershell
npm ci
# 首次创建 .env.local，后端默认 8000 时可直接使用示例值。
Copy-Item .env.example .env.local
# 如果后端是 8001，将其中 VITE_API_PROXY_TARGET 修改为 http://127.0.0.1:8001。
npm run dev
```

已有 `.env.local` 时保留现有配置。打开 Vite 输出地址中的 `/m3/work-orders`，用本地已初始化的测试账号与自己设置的密码登录。修改代理配置后需要重启 Vite。Node.js 使用 22.12+，依赖使用锁定版本。

真实浏览器联调使用独立 `campus_resources_m3_test`，经 Vite 5174 转发至测试后端 8002；日常开发库 `campus_resources` 与后端 8001 分开。测试用合成账号、密码和故障内容，不使用真实业务数据。

已验证：

- 学生登录后返回原工单地址；空列表、上报必填校验、创建后进入真实详情。
- 物业管理员加载真实维修人员并派单；学生页面无管理操作。

- 旧验收弹窗保留第 2 轮；通过测试 API 模拟另一会话驳回并推进到第 3 轮后，旧弹窗提交收到 409，显示冲突提示并刷新到第 3 轮，工单未被误验收。重新确认第 3 轮后成功完成。
- 已完成页面显示追加的完工、驳回、验收和本单维修限制解除记录。
- 另一学生直接访问该工单显示无权查看；列表按状态筛选与恢复正常。
- 桌面 1280×900 和手机 390×844 的列表、详情及手机验收弹窗；手机列表无页面横向溢出。状态筛选条可横向滚动。

这些记录是本地构建、代码审查和浏览器验证，不代表远端 CI 或人工验收。创建的网络超时重试、详情写操作网络错误恢复主要经代码审查核对，本次未注入断网进行浏览器故障测试。

## 6. 保留的范围与限制

- 保持后端原设计：提交完工只提交 `completion_note`。迟到的旧完工请求在返修后可能被识别为下一轮，本次不增加接口字段；前端不自动重试能减少触发，不能消除该服务端限制。详见 `docs/m3-backend.md` 第 8 节。
- 当前已完成文字报修闭环、超时升级、评价与站内通知。附件、细粒度管理范围、撤销/转派、完成后重开、外部通知和跨进程可靠补偿仍未实现，不应当作完整课程 M3 范围已交付。
- Element Plus 当前整体导入，Vite 构建有大包体积提示；构建成功，后续可按项目统一方案优化按需导入。
- 前端通过真实网络调用 M3 后端；M1/M2 业务前端及模块间完整业务 HTTP 联调仍不在本轮范围内。
