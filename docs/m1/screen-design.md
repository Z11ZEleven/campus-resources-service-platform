# 教室屏幕签到（M1）

日期：2026-11-16。范围：M1-003 的屏幕展示与二维码签到。本文是实现说明，不代表组内评审或人工验收。

## 1. 目标

在教室显示器上打开一个页面，显示当天有效的 8 位签到码和二维码；学生用手机扫码后进入签到页，确认自己的预约并完成签到。

不在本次范围：

- 设备绑定与长期设备凭据（阶段二）
- 微信小程序
- 编码按分钟轮换（当前按校园日有效，保留管理员手动轮换）

## 2. 组内已确认的前提

| 事项 | 决定 |
|---|---|
| 网络 | 屏幕、手机与开发机在同一局域网 |
| 屏幕登录 | 使用账号密码登录，不绑定特定设备 |
| 二维码内容 | 前端页面地址 + 教室 + 编码 |
| 公共层改动 | 按需修改，合并后在组内告知 |

## 3. 角色与权限

新增角色 `SCREEN`：

| 项目 | 值 |
|---|---|
| 角色码 | `SCREEN` |
| 权限 | 仅 `m1:checkin_code:read` |
| 数据范围 | 必须是 `ROOM`，绑定具体教室 |
| 会话时长 | `SCREEN_SESSION_MINUTES`，默认 43200 分钟（30 天） |

`SCREEN` 不能读预约、不能改资源、不能改参数。普通学生访问屏幕接口返回 403。

## 4. 后端

### 接口

```
GET /api/v1/m1/screen/rooms/{room_id}/code
```

返回：

```json
{
  "room": { "id": "1", "code": "B1-101", "name": "公共自习室" },
  "code": "12345678",
  "business_date": "2026-11-16",
  "expires_at": "2026-11-16T16:00:00+00:00",
  "version": "1",
  "checkin_path": "/m1/checkin?room=1&code=12345678"
}
```

- 不返回绝对地址，二维码由前端用 `window.location.origin + checkin_path` 生成，因此从局域网 IP 打开屏幕页时二维码也指向同一地址。
- 响应带 `Cache-Control: no-store`。
- 轮询不写审计，避免每 30 秒产生一条日志。

### 编码

沿用现有实现：HMAC(密钥, 教室 + 校园日 + nonce) 取后 8 位。密钥来自 `M1_CHECKIN_SECRET`，数据库只存 nonce 和版本。

### 迁移

`0015_screen_role`：

- 扩展 `d_user_roles.ck_role_code`，加入 `SCREEN`；
- 向 `d_role_permissions` 插入 `SCREEN → m1:checkin_code:read`；
- 降级在有 `SCREEN` 授权时拒绝执行。

## 5. 前端

| 路由 | 页面 | 说明 |
|---|---|---|
| `/screen/:roomId` | `ScreenView.vue` | 全屏展示，未登录时显示内嵌登录表单 |
| `/m1/checkin` | `CheckinLandingView.vue` | 扫码落地页，预填编码，列出本人可签到预约 |

屏幕页行为：

- 每 30 秒刷新一次；
- 每秒更新有效期倒计时；
- 请求失败时隐藏二维码和编码，显示连接中断；
- 不显示常规导航栏。

签到页行为：

- 未登录由路由守卫跳转登录，登录后回到原地址；
- 只显示 `RESERVED` 且属于该教室的预约；
- 签到成功后刷新列表。

## 6. 演示步骤

1. 启动数据库与应用：`docker compose ... up -d mysql`，然后 `.\start.cmd`。
2. 前端以局域网监听启动（见 `start.cmd --lan`）。
3. 屏幕打开 `http://<局域网IP>:5173/screen/<教室ID>`，用 `screen_b1_101` 登录。
4. 手机扫描二维码，用 `student` 登录并签到。
5. 观察预约状态变为“使用中”。

## 7. 验证

## 8. 已知限制

- 二维码可被拍照转发，系统不承诺绝对防代签；
- 演示依赖同一局域网；跨网络需要部署与 HTTPS；
- 阶段一没有设备凭据，屏幕账号密码需由管理员保管。
